# NS 管理记录快捷查看

**先同步，后按 UID 一键查私人档案。** 浏览器用自己的正常登录读取 NodeSeek；自管服务只保留最近 365 天的封禁、解封记录，到期自动清理。不依赖原作者的查询 API，不导出论坛 Cookie。

## 使用

1. [安装或更新油猴脚本](https://raw.githubusercontent.com/xinian5216/ns-seek/main/ns-seek.user.js)，允许访问 `ns.042804.xyz`。
2. 打开 [私人面板](https://ns.042804.xyz:8443)，用自己的专属密码登录。公开源码不提供访问密码或数据库。
3. 同一浏览器正常登录 NodeSeek，在面板点击「连接油猴并打开同步窗口」。五分钟一次性码会自动换取油猴专用密钥，不需要复制密钥。
4. 在论坛窗口手动点击「同步档案」。保持窗口运行，可停止后续传。
5. 回到帖子，点击用户的「管理记录」，直接查私人档案。新增记录需再次手动同步。

面板的「更换密码并撤销旧连接」可生成复杂密码。请先复制到密码管理器，再提交更换；所有旧登录、旧配对码和旧油猴密钥立即作废，其他浏览器也需重新连接。密码只存 scrypt 盐与摘要，服务不保存明文密码。面板会话八小时到期，配对码五分钟到期。

## 范围与隐私

服务只保存有效时间在最近 365 天内的封禁及解封事件。纯鸡腿、星辰调整不入库；复合事件只保存封禁操作及其原因。每小时物理清理一次，查询始终按实时期限过滤，过期记录在等待清理时也不可读取。没有自动数据备份；VPS 提供商快照与已有外部备份不由本程序管理。

记录按数字 UID 匹配，改名不影响匹配。只读、同步和管理权限分开；油猴长期密钥只存 GM 私有存储。查询仅在点击后发出，不保存查询历史，不启用访问日志。论坛 Cookie 仅由浏览器发送给论坛自身，档案服务收不到它。

后端固定监听 `127.0.0.1:18765`，由 HTTPS 8443 反代提供公网入口，公网读取必须认证。固定 Host/Origin 校验，无宽泛 CORS；本地管理控制路径在反代处拦截。既有 443 代理无需调整。独立密码验证不依赖私有网络。

数据库没有磁盘加密，VPS 的 root、服务账户或有权读取磁盘的服务商仍有能力访问。密码与密钥持有人也能访问，因此不能作绝对的「任何其他人都无法访问」保证。详见 [隐私说明](PRIVACY.md)。

## 首次同步与覆盖范围

初始档案为空，不导入他人的数据库。先读最近列表（每页 20 条，最多 100 页），再验证 `/api/admin/ruling/id-N`，从新到旧按编号补采，跳过已经检查的编号。连续 20 条成功读取且时间早于一年的记录后停止；这依赖编号和时间的大致顺序，只是实用停止条件，不证明历史完整。

论坛请求串行，每次完成后至少等待 1.2 秒。遇到登录失效、浏览器验证、限速、网络或字段异常会停止，不自动重试、不绕过验证、不把失败当成空记录。成功空响应会记录编号断点，但不证明记录从未存在。首次补采可能耗时很久，浏览器后台标签页可能休眠。查询无匹配仅代表现有档案未找到。

已验证真实 HTTP/SQLite 的合成采集查询、密码轮换撤销、权限隔离和保留期限。**真实登录论坛＋Tampermonkey 的完整流程仍需用户首次同步验证**，接口不是论坛承诺稳定的第三方 API。Node 22 内置 SQLite 仍带实验标记，本服务固定运行版本并测试。

## 维护与部署

- 运行时零 npm 依赖；Node 22.23.2、SQLite、Caddy、systemd。
- 服务代码 `/opt/ns-seek/app`；私有数据与 scrypt 密码文件 `/var/lib/ns-seek`，目录 0700、文件 0600，仅服务账户/root 可读。
- [systemd 示例](deploy/ns-seek.service) 和 [Caddy 示例](deploy/Caddyfile)。官方 Node 下载包需核对 SHASUMS256，Caddy 按其官方 Debian 稳定源安装。只开放需要的 80/TCP 与 8443/TCP，保留其他现有规则。
- 部署前在私有目录初始化 `secrets.json`，包含独立随机 `queryToken` / `syncToken` / `adminToken`（各 32 随机字节 base64url）、`passwordHash`（由 `backend/password.cjs` 的 `hashPassword()` 生成）及 `publicOrigin`。不能把这个文件提交 Git 或放进安装包。
- 重启：`systemctl restart ns-seek`。升级保留私有数据目录，替换代码后重启。密码文件原子写入，轮换后的密钥重启后仍有效；会话重启后需重新登录。
- 没有服务端论坛登录、后台定时采集或 Cookie 导出；定时任务只清理过期档案。

开发验证：`npm ci --ignore-scripts`、`npm run check`、`npm test`、`npm audit --audit-level=low`。依赖仅供测试。CI 检查版本、固定联网权限、合成测试、依赖漏洞、全 Git 历史与发布目录的密钥。发布只取 Git 跟踪文件，不包含私有数据和真实凭据。
